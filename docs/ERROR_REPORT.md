## [2026-09-20] 补充实际曝光诊断

作者：Codex Agent。

### 发现的问题
- 严重程度：低。用户反馈遮挡镜头和顶部后环境照度不变，目前尚未真机确认原因，不判定传感器故障。
- 已有帧时序回调包含曝光时间，但未在主面板展示，无法直接对比相机曝光与环境光传感器读数。

### 解决方案
- 从当前会话 CaptureResult 保存实际曝光快照，主面板每 500 ms 展示毫秒值并输出原始纳秒日志；不修改请求或原有防抖回调。
- 通过会话代次和 2 秒时效检查避免旧值当作实时值，物理结果缺失不回退到逻辑相机曝光。

### 预防措施
- 单元测试验证小于 1 ms 的精度、缺失、非法值及超时边界；设备测试检查主面板与前后台恢复。
- 本次是诊断信息补充，不宣称修复照度不变，也不将曝光时间直接换算成环境 lux。不启用 EIS。

### 验证结果
- Debug 应用、设备测试包编译通过，32 项单元测试全部通过。
- ADB 无设备，未验证真实遮挡响应、GL/HDR 画面及前后台界面恢复；本轮未重跑全量 Lint。

## [2026-09-20] 主面板静态能力不能代表实时环境照度

作者：Codex Agent。

### 发现的问题
- 严重程度：低。`LUMINANCE_RANGE` 是相机静态能力，本机返回 null，不能作为实时环境光信息使用。
- 直接丢弃短间隔事件可能漏掉变化型传感器最后一次读数；后台继续监听则会产生不必要的工作和过期显示。

### 解决方案
- 主面板改为光线传感器 `TYPE_LIGHT` 的 lux 值，保留一位小数，支持零照度并拒绝 NaN、无穷大与负值。
- 用 500 ms 窗口合并最新事件，不逐帧读取图像；监听绑定页面前台生命周期，与 GL/HDR 和镜头切换独立。
- 暂停时注销监听并取消待发布事件，恢复显示等待读数；没有传感器或监听失败不伪造数值。

### 预防措施
- 保留独立静态能力诊断，不再将其作为实时主面板数据源。环境照度也不能当成镜头目标亮度或可靠的逆光判据。
- 新增单元测试覆盖格式、真实零值与异常值，设备测试覆盖缺失服务、重复启停、实际传感器回调及主面板恢复。
- 不通过照度显示自动开启 HDR、低光增强或系统 EIS。

### 验证结果
- Debug 应用与设备测试包编译通过；29 项单元测试通过，无失败或错误。
- ADB 无连接设备，传感器真实读数、停止回调和前后台界面恢复尚未真机执行；本轮未重跑全量 Lint。

## [2026-09-20] HDR 校准被旧预览依赖阻断

作者：Codex Agent。

### 发现的问题
- 严重程度：高。GL/HDR 校准、绿光入口直接禁用，截图仅支持 TextureView；控制器拒绝全部 HDR 物理会话，UI 错误回退可能使校准样本混入 SDR。

### 解决方案
- GL 独立按需取下一张显示帧，HLG 解码、色域和亮度转换后送入原绿光算法；不含检测框、方向翻转只做一次、超时与取消释放请求。
- 物理镜头 HLG 能力与共有尺寸检查后创建 HDR 物理会话；校准中禁止切换 HDR，失败暂停而不降级。相机切换期间不能采集旧镜头。

### 预防措施
- 回归覆盖旧缓存拒绝、超时后重试、取帧方向和矩阵、HLG 保持、普通校准 UI 与物理切镜头；硬件跳过不算通过。
- 颜色转换可能改变阈值区域，必须用真实 HDR 激光样本重新标定；按需回读会有短暂 GPU 开销，禁止拿此接口实现逐帧 YOLO。
- 禁止启用系统 EIS。物理校准阶段无 SDR YUV，YOLO 暂停是明确约束。

### 验证与残余风险
- 最终真机 5 项回归、22 项 JVM 测试通过；物理广角 5x/长焦/广角切换保持 HLG10，1080x1920 样本成功进入绿光算法，未做实际两距离精度验收。
- 模拟器快照恢复发生系统 EGL_BAD_CONFIG，冷启动后合成测试仍在 GL 队列屏障超时；真机相同测试通过。保留该兼容风险，不将模拟器失败标为通过。
- 全量 Lint 的原有 8 项错误未修复，位于 BLE、语音、MainActivity 与 Manifest；本次相机/校准改动未增加错误。

## [2026-09-15] 普通 GL 无法识别与坐标错帧

历史方案：严格同帧显示策略已由本页首节的异步方案取代。

作者：Codex Agent。

### 发现的问题
- 严重程度：中。GL 模式主动卸载 YOLO、禁用识别按钮，而默认取图依赖已移除的 TextureView。
- 仅解除 UI 限制仍不能解决问题：推理结果晚于预览，最新 EIS 矩阵不属于被识别帧；Compose 框与 GL 图像也不共享提交时钟。
- GPU 模型的创建与执行原先分散在默认线程池，未保证 delegate 线程一致性。

### 解决方案
- 普通 GL 保持模型已加载，并临时选用 YUV 图源；模型生命周期固定到专用线程。

### 预防措施

- 不得把 GL 坐标重复套用 wrapper 变换，也不能使用旋转后外接矩形计算框内判定点。

## [2026-09-15] EIS 同帧同步与 HDR/LSC 集成

作者：Codex Agent。

### 发现的问题
- 严重程度：中。EIS 固定 16 ms 提交节流、Compose 重组及迟到回执可能导致补偿与图像错帧。
- HDR 切换涉及 Camera2 会话与 GL 表面同时重建，旧 Surface/会话回调可能误关新预览。
- LSC 偏好恢复发生在相机能力返回前，过早校验会丢失用户保存的模式。
- 严重程度：低。亮色预览下顶部 HDR/LSC 文字对比度不足，360dp 小屏截图可复现。

### 解决方案
- 同步源项目 EIS 连续性修复和精确时间戳 GL 队列，TextureView 仅匹配当前图像的补偿。
- 使用相机会话代次及 Surface 身份校验；HDR 启动失败恢复 SDR。
- LSC 未读到能力时先保存待应用值，打开相机后校验并回退 AUTO；移植过程的重复接口声明已修正。
- 顶部工具栏增加半透明背景；最终包小屏复测按钮文字清晰且无重叠。
- HDR 通过显式 API 版本入口隔离 Android 13+ 调用；DataSpace 先解析再验证色彩字段；参数迁移合并到偏好初始化，避免无返回值的 Compose remember。

### 验证结果与未解决项
- 6 项 JVM 测试通过；最终包模拟器测试 6 项通过、1 项因无 HLG 显示而跳过。LSC 选项和重启持久化已验证。
- 全量 Lint 剩余 8 项错误均位于本轮未修改文件：`BleConnectionManager.kt` 第 66、87、216 行，`SherpaOnnxHotwordRecognizer.kt` 第 152、165 行，`MainActivity.kt` 第 30、36 行，`AndroidManifest.xml` 第 5 行。
- 前两类为权限检查，后两类为 Fragment 版本要求与 ChromeOS 相机特性声明；未在本轮跨模块修改或全局抑制。该结果不等同于全量静态检查通过。
- HLG10 真机色彩、LSC 实际效果、长焦稳定收益仍需实机验证。

### 预防措施
- 保留重复/乱序时间戳、长帧间隔、GL 像素和 LSC 偏好恢复回归测试。
- 禁止启用系统 EIS；普通 HDR/SDR 预览禁止物理 Surface 绑定。
- 完整参数及验证步骤见 [同步说明](eis-hdr-lsc-sync.md)。
