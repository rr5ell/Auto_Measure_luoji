# 错误报告

## [2026-09-18] 预览缺少实际帧率显示

作者：Codex Agent。

### 发现的问题
- 严重程度：低。相机页无法直观看到预览刷新速度；使用请求 FPS、GL 重绘次数或模型耗时代替会误导性能判断。

### 解决方案
- TextureView 在新纹理更新时计数，GL 在完成新来源图像绘制后计数；按单调时钟实际经过时间计算 FPS，状态区每秒更新。
- 重复时间戳不计数，停帧窗口返回 0，相机关闭/镜头与模式变化清理窗口；GL 和主线程共享计数采用短同步锁，不逐帧更新 Compose 状态。

### 预防措施
- 单元测试覆盖稳定帧率、重复/非法时间戳、延迟采样、停帧、重置与时钟回退；GL 回归验证两张新图像计数及重复绘制零增量。
- 该读数是应用预览新图像处理频率，不代表显示面板扫描频率或系统合成器实际呈现时刻，不用于替代专业帧耗时分析。
- 验证：22 项单元测试、Debug/测试包构建、模拟器普通预览及 GL 页面 FPS 和前后台恢复测试通过；已检查截图，无真机连接，HDR 实机效果待验证。
- GL 综合测试首次在预热阶段失败，第二次通过 FPS 断言后在新鲜空检测框注册时失败，第三次完整通过；保留模拟器时序波动风险，未放宽正式代码的有效期限制。本轮未重跑全量 Lint。

## [2026-09-16] HDR 识别可用但阈值按钮灰色

作者：Codex Agent。

### 发现的问题
- 严重程度：中。模型已支持 HDR 的 SDR YUV 分析流，阈值菜单却仍被 `!hdrPreviewEnabled` 关闭；用户不能调整单框策略和阈值。

### 解决方案
- 只移除参数设置入口的 HDR 限制，不改变模型、默认阈值和已保存数值；复用已有范围校验和识别协程重启逻辑。
- 图源切换、截图校准、防抖标定和绿光识别尚未适配 GL，继续禁用，不批量解禁。
- 验证：17 项 JVM 测试、Debug/测试包构建及 SM-S9480 的 1 项 HDR 页面仪器测试通过；已安装修复包。未重跑全量 Lint，不改变前次混合测试退出停顿的待查结论。

### 预防措施
- 扩展实际页面回归：HDR 下打开菜单、检查阈值可用和图源不可用、打开并保存设置，再确认识别继续运行。
- 相机模式接入新能力时同步检查菜单、对话框、执行循环和结果显示四处准入条件。

## [2026-09-16] HDR 切换丢失识别状态与失效图像读取

作者：Codex Agent。

### 发现的问题
- 严重程度：中。真机 HDR 配置日志为 `yuv=true`，但 `applyHdrPreviewMode()` 仍将 `detectionEnabled` 清零。用户需再点一次识别，容易误认为 HDR 无模型输入。
- 相机关闭时可释放正在使用的 Image；推理返回后读取 `image.timestamp`，真机捕获到 `Image is already closed`。这是结果注册阶段的生命周期竞态。

### 解决方案
- 保留用户识别意图，使用既有 `isCameraReady`、`hdrYoloAvailable` 暂停和恢复循环；清理检测框、性能文本、有效期和测距触发。
- 在提交推理前保存帧时间戳和尺寸，结果注册只用快照；不更换模型，不放宽 200 ms 过期条件。
- 验证：17 项 JVM 测试通过，Debug APK 和测试 APK 构建成功并安装；SM-S9480 分组执行 5 项仪器测试通过，用户现场确认可以识别。

### 预防措施
- 新增 `HdrDetectionToggleInstrumentedTest`，覆盖实际相机页双向切换，要求出现新的模型耗时结果，而非仅检查按钮；同时覆盖识别原本关闭的状态。
- 系统 EIS 保持 OFF，普通逻辑会话不绑定物理输出；框过期与测距触发继续受原有有效期约束。
- 未覆盖：预处理期间关闭 Image 的完整所有权问题、长时间压力与运动目标坐标精度。元数据快照不能视为彻底解决所有相机生命周期竞态。
- 首次混合测试在普通 GL 测试退出时停顿，手动终止后分组重跑全部通过。退出停顿根因尚未确定，不能声称混合套件稳定通过；本轮未重跑全量 Lint。

## [2026-09-15] HDR 无模型输入

作者：Codex Agent。

### 发现的问题
- 严重程度：中。HDR 会话只有 HLG10 预览输出，没有 YUV ImageReader；识别按钮、循环与 GL 框注册也被显式禁用。

### 解决方案
- 检查逻辑相机 HLG10 与 STANDARD 的双向捕获请求约束，空约束表示无限制。
- 允许时新增 STANDARD YUV 输出并加入相同 repeating request；模型只处理 SDR YUV，预览仍保留 HLG10 与 10-bit GL 表面。
- 根据实际创建的分析流开放 HDR 识别与 GL 框；不支持组合则保持 HDR 预览，提示识别不可用。会话配置失败使用原有错误恢复路径。

### 预防措施
- 单元测试覆盖空约束、双向限制、未知配置；HDR 仪器测试覆盖色彩标记、10-bit 精度、YUV 推理与新鲜结果注册。
- 不得用模拟器跳过 HDR 测试的结果声称真机通过，不得将合成框当成模型已识别真实旗杆。
- 不启用系统 EIS，不改变普通会话物理输出绑定，不把 HLG 图像按普通 RGB 输入模型。
- 本轮 17 项 JVM 测试通过，Debug 包和仪器测试包构建成功，应用已更新；手机锁屏，尚未执行 HDR 实机回归，真实目标检出与画质仍待核验。

## [2026-09-15] GL 配对仍限制模型输入

作者：Codex Agent。

### 发现的问题
- 严重程度：中。异步预览方案仍在推理前要求 GL 来源元数据精确命中；未命中便跳过 detectFromYuv，解耦不完整。
- 真机现有日志显示另一种情况：GL 开启时 LOCAL_GPU 正常完成推理，但返回 0 个目标。不能把所有无框现象都归因于未调用模型。

### 解决方案
- YUV 先进入 YOLO，之后才注册 GL 结果；GL 注册允许来源帧未被预览消费。
- 保留源时间戳和取帧单调时间，显示仍检查 200 ms 有效期；日志分别记录模型完成和框是否可显示。

### 预防措施
- 合成测试加入从未渲染过的 YUV 时间戳，验证仍可注册异步结果；真实相机测试必须先调用模型，再接触 GL 注册。
- 不因返回 0 个目标擅自降低阈值或替换模型；需要可复现目标画面核对输入和输出。
- 验证：14 项 JVM 测试与 2 项模拟器仪器测试通过。相机测试先确认预览启动，再验证推理期间前进；GL 无票据与未运行模型分别判定。已更新真机应用，现场目标检出仍待解锁后核验。

## [2026-09-15] 识别拖慢 GL 预览

作者：Codex Agent。

### 发现的问题
- 严重程度：中。旧路径以“固定纹理且推理完成”为显示条件，预览吞吐受 YOLO 限制，与 EIS 是否开启无关。

### 解决方案
- 预览只依赖相机和 EIS 帧矩阵；YOLO 独立运行，只缓存来源帧元数据和最新结果。
- 不固定整帧纹理，不把框烘焙进预览缓存；框最多保留 200 ms，空结果立即替换。
- 同时使用相机时间戳和单调时钟判断过期，停止出帧仍能清框；过期结果不得继续触发测距。

### 预防措施
- 测试中故意延迟推理，断言相机画面仍连续前进。
- 必须区分来源时间戳与预览时间戳；此版本不包含光流/目标跟踪，不保证运动目标的瞬时定位精度。
- 当前测试结果见 [异步识别说明](gl-yuv-detection.md)。
- 模拟器首次文字/诊断合成耗时会使测试帧过期；像素测试先预热两条渲染路径，再使用新帧验证，不放宽正式有效期。本轮 14 项单元测试及 2 项仪器测试通过，冷启动及真机负载表现仍需实测。

## [2026-09-15] 普通 GL 无法识别与坐标错帧

历史方案：严格同帧显示策略已由本页首节的异步方案取代。

作者：Codex Agent。

### 发现的问题
- 严重程度：中。GL 模式主动卸载 YOLO、禁用识别按钮，而默认取图依赖已移除的 TextureView。
- 仅解除 UI 限制仍不能解决问题：推理结果晚于预览，最新 EIS 矩阵不属于被识别帧；Compose 框与 GL 图像也不共享提交时钟。
- GPU 模型的创建与执行原先分散在默认线程池，未保证 delegate 线程一致性。

### 解决方案
- 普通 GL 保持模型已加载，并临时选用 YUV 图源；模型生命周期固定到专用线程。
- 先固定同时间戳纹理和采样矩阵，再推理；图像与框写入同 FBO，按模型速度成对推进。
- 缺少同帧纹理、矩阵或过期结果直接丢弃；取消、模式切换、尺寸变化时释放固定资源。

### 预防措施
- 保留旋转、镜像、裁切、Roll、同帧像素、固定帧保留、旧结果拒绝和真实相机 YUV 推理闭环测试。
- 不得把 GL 坐标重复套用 wrapper 变换，也不能使用旋转后外接矩形计算框内判定点。
- 具体测试结果与硬件约束见 [GL 同帧识别](gl-yuv-detection.md)。

### 验证结果
- 10 项 JVM 测试通过；真机同帧像素及 YUV 模型闭环测试通过，GL 识别、图源恢复和前后台切换已检查。
- 全量 Lint 原有 8 项错误未解决，本轮没有新增错误；现场未检出旗杆，真实目标精度仍待验证。

## [2026-09-15] EIS 同帧同步与 HDR/LSC 集成

作者：Codex Agent。

### 发现的问题
- 严重程度：中。EIS 固定 16 ms 提交节流、Compose 重组及迟到回执可能导致补偿与图像错帧。
- HDR 切换涉及 Camera2 会话与 GL 表面同时重建，旧 Surface/会话回调可能误关新预览。
- LSC 偏好恢复发生在相机能力返回前，过早校验会丢失用户保存的模式。
- 严重程度：低。亮色预览下顶部 HDR/LSC 文字对比度不足，360dp 小屏截图可复现。

### 解决方案
- 同步源项目 EIS 连续性修复和精确时间戳 GL 队列，TextureView 仅匹配当前图像的补偿。
- 使用相机会话代次及 Surface 身份校验；HDR 启动失败恢复 SDR。
- LSC 未读到能力时先保存待应用值，打开相机后校验并回退 AUTO；移植过程的重复接口声明已修正。
- 顶部工具栏增加半透明背景；最终包小屏复测按钮文字清晰且无重叠。
- HDR 通过显式 API 版本入口隔离 Android 13+ 调用；DataSpace 先解析再验证色彩字段；参数迁移合并到偏好初始化，避免无返回值的 Compose remember。

### 验证结果与未解决项
- 6 项 JVM 测试通过；最终包模拟器测试 6 项通过、1 项因无 HLG 显示而跳过。LSC 选项和重启持久化已验证。
- 全量 Lint 剩余 8 项错误均位于本轮未修改文件：`BleConnectionManager.kt` 第 66、87、216 行，`SherpaOnnxHotwordRecognizer.kt` 第 152、165 行，`MainActivity.kt` 第 30、36 行，`AndroidManifest.xml` 第 5 行。
- 前两类为权限检查，后两类为 Fragment 版本要求与 ChromeOS 相机特性声明；未在本轮跨模块修改或全局抑制。该结果不等同于全量静态检查通过。
- HLG10 真机色彩、LSC 实际效果、长焦稳定收益仍需实机验证。

### 预防措施
- 保留重复/乱序时间戳、长帧间隔、GL 像素和 LSC 偏好恢复回归测试。
- 禁止启用系统 EIS；普通 HDR/SDR 预览禁止物理 Surface 绑定。
- 完整参数及验证步骤见 [同步说明](eis-hdr-lsc-sync.md)。
