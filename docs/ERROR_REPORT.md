# 错误报告

## [2026-09-21] 中心区域曝光参考

作者：Codex Agent。

### 发现的问题
- 严重程度：中。原预览没有区域测光请求，逆光时默认测光可能优先照顾高亮背景，中心目标曝光不足；这是能力补充，不是对具体手机故障的确诊。
- 直接固定传感器矩形会忽略预览宽高比、裁切变焦或纯 UI 放大；将 CONTROL_ZOOM_RATIO 再除一次会导致参考区域过小。
- 厂商可能不支持/拒绝 AE 区域，持久化开关不能等同于 HAL 已生效；校准已有 -2 EV 行为必须保持。
- 回归发现关闭后恢复模板 `(0,0,0,0,weight=0)` 时，模拟器 CaptureResult 仍回传旧中心区域；零面积重置可能被 HAL 忽略，不能只验证 Builder。
- 界面复查发现新增提交检查若对过期会话抛异常，原错误回调会将其显示成 HDR 故障；迟到回调不能污染当前会话状态。

### 解决方案
- 先映射预览有效范围，再取中心宽高各 30%；能力检查、逻辑相机坐标、模板默认区域恢复与单次失败回退集中在 centermetering 模块。
- 开关只改变 AE 区域，校准暂停，关闭或拒绝恢复默认。主面板明确“已请求”，日志输出请求/结果，不声称必定提亮。
- 无有效加权模板区域时改用合法全幅零权重矩形恢复默认测光语义，避免空矩形被丢弃；有有效模板加权区域时原样恢复。
- 新增提交路径忽略不再匹配的 session/builder，且不发布 onCameraOpened；这不是对原有全部 CameraDevice 关闭竞争的修复。
- 81 项单元测试、Debug 应用/测试包构建及 laserCompare Kotlin 编译通过；三项设备回归通过，覆盖真实 CaptureResult 开关恢复、模板 AF/EV/AE_LOCK/EIS 保持、开关持久化及原菜单。默认与窄屏大字体截图检查通过。
- 模拟器实际回传中心区域 `(650,540,557,313,weight=1000)`，关闭后回到全幅零权重；此结果仅证明区域请求/恢复，不证明真实逆光画质改善。未执行全量设备回归或真机 HDR 测试。

### 预防措施
- 禁止启用 EIS；测光基于相机原始预览中心，不跟随校准锚点平移或运动补偿，避免把显示坐标直接当成传感器坐标。
- 真机验证时同时看曝光时间、ISO、目标纹理及天空过曝程度；自动 HDR 仍按原曝光规则判断，中心测光可能间接改变其触发条件。
- 既有 CameraDevice 关闭竞争不在本次范围，不把设备请求接受当作曝光改善证明。

## [2026-09-21] 轻量眩光抑制试验

作者：Codex Agent。

- 局部最暗值不等于真实杂散光，平坦天空、彩色区域及运动边缘可能被误处理；不能把变黑或视觉更锐利当作真实细节恢复。

- 新增显示端可关闭的互斥试验模式，限制白雾扣除量，平坦邻域不处理，高光渐退，最低 RGB 通道最多扣除一半，保留原始算法输入。
- 复用现有普通预览 RenderEffect 与 GL 最终屏幕合成，不改相机会话；校准由已有 forCalibration 覆盖为 OFF。
- 75 项单元测试、Debug 应用/测试包构建及 laserCompare Kotlin 编译通过；两条 GPU 路径像素与原图隔离、菜单互斥/持久化三项重点回归分别通过。默认/320dp 窄屏及 1.3 倍字体菜单无新增重叠。
- 全量设备测试在已有曝光回归阶段被模拟器 system_server 的 EGL_BAD_CONFIG 崩溃中断。冷启动后串行 TextureView -> GL 仍出现预热超时/ANR，根因未确认；切换主机 GPU 后 GL 单独运行及菜单单独运行通过。未修改相机代码来规避测试，不宣称全量设备回归通过。

### 预防措施
- 禁止启用 EIS；未验证检测框、质心误差前不得把抑制结果用于测量。
- 无时域滤波，固定稀疏邻域仍可能产生光晕、噪声或闪烁；需真实逆光视频与长时间帧率评估。
- HLG 使用编码域启发式处理，不声称等同物理去眩光；既有 CameraDevice 关闭竞争不在本次修改范围。

## [2026-09-21] 局部色调映射与 Retinex 预览试验

作者：Codex Agent。

### 发现的问题
- 严重程度：中。原像素级暗部曲线不考虑邻域或照明分布，画面变亮不等于主体纹理更清楚。

### 解决方案
- 新增互斥模式：对数亮度双边分解的局部色调映射，以及单尺度高斯照明估计的 Retinex；固定邻域和参数，不使用逐帧全局 min/max 拉伸。

- Android 13 以下普通预览明确提示需 GL；不开启系统 EIS，不自动切换渲染器，不改已有 HDR 状态机。
- 新 TextureView 创建时清零尺寸状态，避免从 GL 切回相同尺寸普通预览时布局值未变化、效果未重新提交。

### 预防措施
- 同步验证均匀暗部、黑白端点、邻域变化、双边边缘保护、增益上限和色域保护，不能只检测开关是否变为开启。
- 使用 PixelCopy 核对上屏像素，与未修改的 TextureView/GL 原图对照；UI 验证互斥及 Activity 重建恢复。
- 稀疏邻域是为实时显示所做的近似，并非完整 MSRCR 或多帧 HDR。存在光晕、噪声放大和 GPU 性能风险，需实际逆光素材和真机评估。

### 验证结果
- 69 项单元测试全部通过，Debug 应用、设备测试包构建及 laserCompare Kotlin 编译通过。
- 首轮及最终包各 10 项模拟器回归通过；TextureView 与 GL 的两种增强像素符合 CPU 参考，亮暗交界验证邻域影响，原始取帧/缓存不变，关闭后恢复。
- 菜单验证两个新增模式与原暗部曲线互斥，Retinex 经 Activity 重建保留；默认屏幕和 320dp/1.3 倍字体下文案与开关无重叠。
- 尺寸/字体变化后的相机重建仍可触发此前已知 CameraDevice was already closed 提示，本轮未改动控制器竞争逻辑。
- 当前未连接真机，HLG 实际画质、真实逆光目标细节、长期帧率及旧 Android 实机未验证；未重跑全量 Lint。

## [2026-09-21] 暗部增强与顶部菜单收纳

作者：Codex Agent。

### 发现的问题
- 严重程度：中。ColorMatrix 只能线性变换颜色，不能独立提升暗部且保留高光；将效果烘焙入预览缓存则会改变模型及校准输入。
- 本轮像素测试实测发现：此前 TextureView.setLayerPaint 对比度 0.8 会将 getBitmap 的灰阶值从 51 改为 66，证明原有对比度会污染算法取帧。根因为 getBitmap 复制硬件纹理层时包含该层 paint。
- 顶部 HDR、LSC 和 EV 等按钮挤占主操作区域；测试包还额外固定绿光对比入口。

### 解决方案
- 复用现有最终上屏合成，加入共享的非线性暗部增益函数；TextureView 使用 Android 13+ RenderEffect/RuntimeShader，GL 使用最终屏幕 Shader。
- 修正普通预览原有对比度隔离：API 31+ 统一使用 RenderEffect，API 24~30 仅在专属 FrameLayout 硬件层应用颜色矩阵，TextureView 的 layer paint 始终中性。
- 所有颜色处理仅针对画面显示节点，不影响叠加框、坐标及算法取帧；校准临时关闭效果，不改写用户偏好。旧系统普通预览禁用开启并提示需 GL。
- 顶部仅保留四个主入口，其余工具统一进入可滚动“更多”，保留原来的业务回调与锁定条件。

### 预防措施
- 验证灰阶单调、端点、增益/色域界限及 SDR/HLG 权重；像素回归同时检查显示改变与原图不变，菜单测试检查开关保存和重建恢复。
- 禁止启用 EIS；不为显示增强重建相机会话。本次不修复已知 HDR 切换竞争；厂商 HLG 色彩、连续帧率及真实逆光画质需真机确认。

### 验证结果
- 65 项单元测试、Debug 应用与设备测试包构建、laserCompare Kotlin 编译通过；模拟器 10 项设备回归通过。
- 初次 TextureView 像素测试发现对比度污染原图，修正后复测通过；API 31+ RenderEffect 路径和旧系统父容器滤镜路径均在当前模拟器验证，未在 API 24~30 实机执行。
- 默认屏幕与 320dp/1.3 倍字体截图确认新增按钮/菜单无重叠；普通校准中开关禁用，偏好保持开启。
- 改变模拟器密度/字体引起 Activity 重建时复现已知 CameraDevice was already closed，堆栈位于 Camera2Controller.startPreview:547 / createLogicalSession.onConfigured:462；恢复后仍有预览但保留错误提示。本轮未修改此竞争逻辑。
- 真机 HLG 画质和持续帧率未验证，未重跑全量 Lint；不将模拟器软件 GPU 帧率视为手机性能结论。

## [2026-09-20] 自动 HDR 的反复切换与手动竞争防护

作者：Codex Agent。

### 发现的问题
- 严重程度：中。HDR 切换会重建相机会话；直接按曝光逐帧开关，可能频繁打断预览与识别，也可能中断校准、测量。
- 异步能力检查返回时，镜头、自动模式、参数或业务流程可能已经变化；旧决定不能直接执行。

### 解决方案
- 独立状态机使用单调时钟，成功切换才开始双向停判；默认 10 秒内不判断或缓存曝光条件，结束后只读新鲜 CaptureResult。
- 开启条件为曝光严格小于下限或大于上限；关闭条件含两端边界。直接使用原始纳秒值换算，不使用界面四舍五入后的数值。
- 校准、测距、统计、后台和未就绪时暂停切换；自动开启时禁用手动 HDR，关闭自动后保留当前 HDR 状态。
- 旧 HDR 切换逻辑会清除绿光对比和防抖标定状态，因此这两种运行状态也必须阻止自动切换。
- 异步结果执行前再次校验参数版本、模式、镜头、业务状态和当前曝光；能力或会话失败停止自动模式，避免自动重试循环。

- 普通 GL 保持模型已加载，并临时选用 YUV 图源；模型生命周期固定到专用线程。
- 先固定同时间戳纹理和采样矩阵，再推理；图像与框写入同 FBO，按模型速度成对推进。
- 缺少同帧纹理、矩阵或过期结果直接丢弃；取消、模式切换、尺寸变化时释放固定资源。

### 预防措施
- 保留旋转、镜像、裁切、Roll、同帧像素、固定帧保留、旧结果拒绝和真实相机 YUV 推理闭环测试。
- 不得把 GL 坐标重复套用 wrapper 变换，也不能使用旋转后外接矩形计算框内判定点。
- 具体测试结果与硬件约束见 [GL 同帧识别](gl-yuv-detection.md)。

### 验证结果
- 10 项 JVM 测试通过；真机同帧像素及 YUV 模型闭环测试通过，GL 识别、图源恢复和前后台切换已检查。
- 全量 Lint 原有 8 项错误未解决，本轮没有新增错误；现场未检出旗杆，真实目标精度仍待验证。

## [2026-09-15] EIS 同帧同步与 HDR/LSC 集成

作者：Codex Agent。

### 发现的问题
- 严重程度：中。EIS 固定 16 ms 提交节流、Compose 重组及迟到回执可能导致补偿与图像错帧。
- HDR 切换涉及 Camera2 会话与 GL 表面同时重建，旧 Surface/会话回调可能误关新预览。
- LSC 偏好恢复发生在相机能力返回前，过早校验会丢失用户保存的模式。
- 严重程度：低。亮色预览下顶部 HDR/LSC 文字对比度不足，360dp 小屏截图可复现。

### 解决方案
- 同步源项目 EIS 连续性修复和精确时间戳 GL 队列，TextureView 仅匹配当前图像的补偿。
- 使用相机会话代次及 Surface 身份校验；HDR 启动失败恢复 SDR。
- LSC 未读到能力时先保存待应用值，打开相机后校验并回退 AUTO；移植过程的重复接口声明已修正。
- 顶部工具栏增加半透明背景；最终包小屏复测按钮文字清晰且无重叠。
- HDR 通过显式 API 版本入口隔离 Android 13+ 调用；DataSpace 先解析再验证色彩字段；参数迁移合并到偏好初始化，避免无返回值的 Compose remember。

### 验证结果与未解决项
- 6 项 JVM 测试通过；最终包模拟器测试 6 项通过、1 项因无 HLG 显示而跳过。LSC 选项和重启持久化已验证。
- 全量 Lint 剩余 8 项错误均位于本轮未修改文件：`BleConnectionManager.kt` 第 66、87、216 行，`SherpaOnnxHotwordRecognizer.kt` 第 152、165 行，`MainActivity.kt` 第 30、36 行，`AndroidManifest.xml` 第 5 行。
- 前两类为权限检查，后两类为 Fragment 版本要求与 ChromeOS 相机特性声明；未在本轮跨模块修改或全局抑制。该结果不等同于全量静态检查通过。
- HLG10 真机色彩、LSC 实际效果、长焦稳定收益仍需实机验证。

### 预防措施
- 保留重复/乱序时间戳、长帧间隔、GL 像素和 LSC 偏好恢复回归测试。
- 禁止启用系统 EIS；普通 HDR/SDR 预览禁止物理 Surface 绑定。
- 完整参数及验证步骤见 [同步说明](eis-hdr-lsc-sync.md)。
